# Schema Functions Reference

Locality IDB provides declarative builders to set up schemas.

## `defineSchema`

Defines your complete database schema from an object mapping table names to column configurations.

```typescript
function defineSchema<S extends ColumnRecord>(schema: S): Schema<S>
```

### Example

```typescript
import { defineSchema, column } from 'locality-idb';

const schema = defineSchema({
  users: {
    id: column.int().pk().auto(),
    name: column.text(),
  },
  posts: {
    id: column.int().pk().auto(),
    title: column.text(),
  },
});
```

## `table`

An alternative function to define a single table in isolation.

```typescript
function table<Col extends ColumnDefinition>(name: string, columns: Col): Table<Col>
```

### Example

```typescript
import { table, column } from 'locality-idb';

const userTable = table('users', {
  id: column.int().pk().auto(),
  name: column.text(),
});

const idb = new Locality({
  dbName: 'my-database',
  version: 1,
  schema: {
    users: userTable,
  },
});
```

:::danger[Warning]
In most cases, prefer `defineSchema()` over `table()`. It keeps your schema in a single place, improves readability, and eliminates the possibility of table name mismatches.

When using `table()`, the table name passed to the function **must exactly match** the corresponding key in the `schema` object passed to `Locality` Constructor. TypeScript infers table names from the schema object keys, while Locality IDB uses the name passed to `table()` at runtime. If the two differ, your code may compile incorrectly or fail at runtime.

Example:

```typescript
import { Locality, table, column } from 'locality-idb';

const usersTable = table('users', {
  id: column.int().pk().auto(),
  name: column.text(),
});

const postsTable = table('postsMany', {
  id: column.int().pk().auto(),
  title: column.text(),
});

const idb = new Locality({
  dbName: 'my-database',
  version: 1,
  schema: {
    users: usersTable,
    posts: postsTable,
  },
});
```

In this example, TypeScript recognizes the table as `'posts'`, but Locality IDB looks for `'postsMany'` at runtime.

```typescript
await idb.from('posts').findAll(); // Compiles, but throws at runtime.
await idb.from('postsMany').findAll(); // Works at runtime, but TypeScript reports an error.
```

In the following example, both table name and schema object key name are same and works properly.

```typescript
await idb.from('users').findAll(); // This works without any issue
```

Using [`defineSchema()`](#defineschema) avoids this kind of errors entirely. It handles table names internally using the keys.
:::
