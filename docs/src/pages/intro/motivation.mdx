# Why Locality IDB?

:::tip
`IndexedDB` is a powerful browser-native database that supports storing significant amounts of structured data, including files and blobs. However, the raw browser `IndexedDB` API is low-level, verbose, and uses event-driven listeners instead of promises or modern control flows.
:::

`Locality IDB` was built to address these shortcomings by providing a developer-friendly query builder that feels like a modern SQL ORM (specifically Drizzle ORM).

## Why Not Raw IndexedDB?

If you are weighing whether to use `Locality IDB` or write raw `IndexedDB` API calls, consider the advantages of Locality IDB:

- **Type safety**: Schema-driven types reduce compile-time and runtime errors. Your queries automatically infer the return types of selected tables.
- **Query ergonomics**: A fluent, chainable builder replaces hundreds of lines of cursor, transaction, and request handler boilerplate.
- **Reference handling**: Foreign key relationships are automatically enforced, and cascading updates/deletes are handled for you.
- **Built-in Validation**: Column type checks and constraints run automatically before writing to the database.
- **Consistency**: Declaring a single source of truth (the schema) makes it easy to keep data access uniform across your application.

## Choosing the Right Tool

The IndexedDB ecosystem offers several excellent libraries, each with a different design philosophy and target use case.

| Library         | Best For                                                                                                          |
| :-------------- | :---------------------------------------------------------------------------------------------------------------- |
| `Raw IndexedDB` | Applications that need maximum control with minimal abstraction.                                                  |
| `idb-keyval`    | Simple key-value storage, such as preferences, settings, or small caches.                                         |
| `idb`           | Projects that want a lightweight Promise-based wrapper while staying close to the native `IndexedDB` API.         |
| `Dexie.js`      | Developers looking for a mature `IndexedDB` wrapper with a flexible API and extensive plugin ecosystem.           |
| `Locality IDB`  | Developers who prefer a declarative, schema-first, SQL-like workflow with built-in validation and type inference. |

:::tip[When to Use Locality IDB]
`Locality IDB` is **not intended to replace** libraries like `idb` or `Dexie.js`. Instead, it provides a different developer experience for those who prefer a declarative, schema-first, SQL-like approach to working with `IndexedDB`. Its goal is to bring a familiar ORM-style workflow with strong type inference and built-in validation to `IndexedDB`, the browser's native database.

If you already use tools like **Drizzle ORM** or **Prisma** on the backend and want a familiar ORM-style workflow for `IndexedDB`, `Locality IDB` is designed with that workflow in mind.:::
